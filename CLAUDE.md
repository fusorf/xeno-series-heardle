# Xeno Series Heardle - Claude Development Guide

## Project Overview
A daily music guessing game (Heardle clone) for the Xeno video game series (Xenoblade, Xenosaga, Xenogears). 723 songs across 14 games. Fully client-side, no backend.

## Tech Stack
- **100% vanilla JavaScript** — no frameworks, no build step, no bundler
- HTML5 Audio API for playback
- localStorage for state persistence
- CSS3 with dynamic stylesheet injection + CSS custom properties
- Audio files hosted on Cloudflare R2
- i18n via JSON locale files (EN/FR/DE/ES/IT/JA/KO/ZH)

## Architecture

### File Responsibilities
| File | Role |
|------|------|
| `index.html` | Single HTML entry point, loads all JS via `<script>` tags |
| `style.css` | Global styles, responsive layout, component styles |
| `js/constants.js` | `DURATIONS`, `MAX_ATTEMPTS`, `DEFAULT_MODE` |
| `js/songs.js` | Song database (723 entries), `GAMES` metadata, `GAME_MODES`, `SONG_POOLS` |
| `js/random.js` | Seeded PRNG (`mulberry32`), deterministic daily song selection, cycle system |
| `js/game.js` | Main orchestrator — init, game loop, mode switching, endless/blitz integration, volume control |
| `js/storage.js` | localStorage wrapper (`storageGet`/`storageSet`), history management, backfill |
| `js/theme.js` | Two-level CSS theme system (gamemode themes + game themes) |
| `js/player.js` | HTML5 Audio wrapper, progress bar, playback timing (timeupdate events + safety timeout) |
| `js/ui.js` | DOM rendering, event listeners, autocomplete, mobile keyboard handling, mobile toolbar setup |
| `js/blitz.js` | 60-second rapid-fire mode, combo UI, audio preloading, state machine |
| `js/guesser.js` | Game Guessr mode — identify which game a song belongs to (A/B choice, 3 lives) |
| `js/version.js` | Auto-generated by pre-commit hook (do not edit manually) |

### Data Flow
1. `initGame()` → load locale → render mode tabs → get daily song → apply theme → load saved state or fresh game
2. User guess → validate → increment attempt → save state → re-render UI
3. Mode switch → `switchMode()` → cleanup players → save preference → init new mode
4. Game end → `endGame()` → load game theme → render results → save to history

### Module Communication
- Global variables within each module (no ES modules, no imports)
- Cross-module calls via global functions (e.g., `ui.js` calls `game.js` functions)
- All JS files loaded in dependency order in `index.html`
- No cross-module state mutations — communicate via function calls

## Key Conventions

### Code Style
- Section headers: `// ============================================`
- Descriptive function names in camelCase
- Constants in UPPER_SNAKE_CASE
- Game IDs use kebab-case: `xenoblade-1`, `xenosaga-3`, `xenoblade-2-torna`
- Comments in English, UI text via locale system
- No semicolons are NOT a pattern here — semicolons ARE used

### localStorage Keys
- Mode preference: `xenoHeardleMode`
- Language: `xenoHeardleLanguage`
- Daily state: `xenoHeardle_{mode}_state`
- Daily history: `xenoHeardle_{mode}_history`
- Endless history: `xenoHeardle_{mode}_endless`
- Blitz history: `xenoHeardle_{mode}_blitz`
- Blitz high score: `xenoHeardle_blitz_highscore`
- Blitz stats: `xenoHeardle_blitz_stats`
- Guesser history: `xenoHeardle_{mode}_guesser`
- Volume: `globalVolume` (0–1 float)

### Song Entry Format
```javascript
{ title: 'Song Name', japaneseTitle: 'JP名', file: 'filename.mp3', duration: 180, game: 'xenoblade-1', composer: 'Name', artist: 'Name' }
```
- `composer` is the **primary credit** field (displayed by default)
- `artist` is optional — only present when it differs from composer (e.g., arranger vs original composer)
- `japaneseTitle` is optional
- `localizedTitle` for region-specific names
- `duration` must be > 16 for random-start modes
- `file` is the MP3 filename (**with** `.mp3` extension) in the R2 bucket

### Theme System
- Gamemode CSS: `themes/gamemodes/{mode}.css` — sets colors/fonts during gameplay
- Game CSS: `themes/games/{game-id}.css` — overrides on results screen
- CSS variables: `--theme-primary`, `--theme-secondary`, `--theme-accent` + `-rgb` variants
- Fonts: `--theme-font-heading`, `--theme-font-body`

### Game Modes
| Mode ID | Scope | Description |
|---------|-------|-------------|
| `full-xeno` | All games except Pied Piper | Default daily mode |
| `xenoblade` | 8 Xenoblade games | Daily mode |
| `xenosaga` | 3 Xenosaga games | Daily mode |
| `random` | All 14 games | Daily + random game + random start time |
| Endless | Overlay on any mode | Infinite rounds, optional game lock |
| Blitz | Overlay on any mode | 60s timer, combo multiplier |
| Game Guessr | Overlay on any mode | Identify which game a song belongs to (A/B, 3 lives) |

### Timing
- Epoch date: 2026-02-09 (Day 1)
- Song changeover: 23:00 UTC (1 hour before midnight)
- Cycle length: 20 days (avoids recent repeats)
- Clip durations by attempt: 1s → 3s → 7s → 14s → 16s

## Development Notes

### No Build Step
Files are served as-is. To develop locally, use any static file server:
```bash
npx serve .
# or
python -m http.server
```

### Testing
No test framework. Debug utilities available in browser console on localhost:
- `clearAllData()` / `clearModeData(mode)` / `showData()`
- `previewUpcomingSongs(mode, count)` — preview daily song schedule
- `testRandomnessQuality(mode, count)` — verify PRNG distribution
- `setDateOverride('YYYY-MM-DD')` — simulate a different date

### Adding a New Song
1. Add entry to `SONG_POOLS[gameId]` in `js/songs.js`
2. Upload MP3 to R2 in the correct game folder
3. Ensure `duration` is accurate (seconds)
4. Song will automatically appear in autocomplete and daily rotation

### Adding a New Game
1. Add game metadata to `GAMES` object in `js/songs.js`
2. Add song pool to `SONG_POOLS`
3. Add game to relevant `GAME_MODES[mode].games` arrays
4. Create `images/{game-id}/background.webp` and `cover.jpg`
5. Create `themes/games/{game-id}.css` with color overrides
6. Add game to filter chips in stats modal

### Commit Messages
- Short, lowercase descriptions: `fix music start`, `support clavier`, `Blitz mode`
- No conventional commits prefix required
- French or English are both fine

### Audio URL Pattern
```
{AUDIO_BASE_URL}/music/{GAMES[gameId].folder}/{encodeURIComponent(song.file)}
```

### Important Gotchas
- `version.js` is auto-generated — never edit manually
- Songs with `duration < 16` cannot be used in random-start modes
- The `random` mode reveals which game a song is from only after guessing
- DLC games have a `parentGame` field and `isDLC: true`
- Responsive breakpoint is 900px (single breakpoint)
- All state is per-mode isolated — switching modes doesn't affect other modes' progress
- Progress bars use `timeupdate` events (not rAF) with CSS `transition: width 0.25s linear` for smooth display
- Short audio clips (1s) use a safety `setTimeout` to guarantee stop, since `timeupdate` fires ~4x/sec
- On mobile (≤900px), toolbar buttons (endless, blitz, guesser, stats, lang) are moved into a horizontal row under the pool selectors via `setupMobileToolbar()` in ui.js
